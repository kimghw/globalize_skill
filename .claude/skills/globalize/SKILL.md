# 프로젝트 스킬 전역화 (globalize)

프로젝트 스킬을 전역 `~/.claude/skills/`에 복사해 어떤 프로젝트에서든 사용할 수 있게 한다.

**원칙: 원본(source of truth)은 항상 프로젝트 쪽 스킬 폴더, 전역에는 복사본만 둔다.**
전역 복사본 안의 `.globalize.json` 사이드카에 원본 경로·제외 목록·git 저장소 정보가 기록되며, `sync`는 이 기록대로 원본 → 전역을 미러링한다(원본에서 지워진 파일은 전역에서도 제거, 제외 경로는 보호). 사이드카가 없는 전역 스킬은 이 도구가 절대 건드리지 않는다.

모든 실제 작업은 `scripts/globalize.ps1`이 수행한다.

## 실행 방법

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<이 SKILL.md가 있는 폴더>\scripts\globalize.ps1" <action> [인자...]
```

| 사용자 요청 | action |
|---|---|
| 전역 스킬 현황 / 동기화 필요 여부 확인 | `list` (각 원본 프로젝트의 git 상태 — 미커밋/미푸시/원격 유무 — 도 함께 표시) |
| 프로젝트 스킬을 전역에 등록 | `add <스킬폴더경로>` 또는 현재 프로젝트 스킬이면 `add <이름>` (데이터 폴더는 `-Exclude 폴더명,...`으로 제외) |
| 원본과 동일한지 확인하고 다르면 전역에 반영 | `sync <이름>` 또는 전체 `sync` (`update`도 동일 동작 - 이미 같으면 "이미 최신 상태" 출력) |
| 전역 스킬을 원본과 동기화하고 원본 프로젝트를 커밋+푸시 | `git [커밋메시지]` (아래 "git 액션" 참조) |
| 전역 복사본 제거 (원본은 유지) | `remove <이름>` |
| 새 PC로 이전 후 전역 스킬 일괄 복원 | `restore` (레지스트리 기반, 아래 "이전/복원" 참조) |
| 세션 시작 시 자동 동기화 훅 설치/갱신 | `install-hook` |

- 인자 없이 호출되면 아래 "관리 흐름"을 따른다.
- `add`는 같은 이름의 전역 스킬이 이미 있으면(관리 대상이 아닌 경우) 실패한다. 사용자가 덮어쓰기를 확인해준 경우에만 `-Force`를 추가한다.
- `-Exclude`는 경로 세그먼트(폴더/파일 이름) 단위로 일치하며 사이드카에 저장되어 이후 `sync`에도 계속 적용된다. 제외된 경로는 전역 쪽에 있어도 삭제하지 않는다.
- 원본 프로젝트가 이동했으면 새 경로에서 `add`를 다시 실행하면 원본 경로가 갱신된다.

## git 액션 — 동기화 + 원본 저장소 커밋/푸시

사용자가 "globalize git"을 요청하면 한 번에 다음을 수행한다:

1. 관리 대상 전역 스킬 전체를 원본과 동기화(전체 `sync`와 동일)하고 레지스트리를 갱신한다.
2. 각 원본이 속한 git 저장소마다(같은 저장소를 쓰는 스킬들은 한 번만): 미커밋 변경이 있으면
   `add -A` → commit, 원격이 있으면 push. 원격이 없으면 푸시를 건너뛰고 안내만 출력한다.

- 커밋 메시지: 실행 전에 원본 저장소의 diff(`git -C <root> diff HEAD --stat` 등)를 확인해
  **한국어 1줄 메시지를 만들어 인자로 전달**한다(`git "<메시지>"`). 생략하면
  "스킬 갱신: <스킬이름들>" 기본 메시지가 쓰인다.
- 이 액션은 사용자가 명시적으로 요청한 것이므로 커밋/푸시 전에 별도로 묻지 않는다.
- 푸시 실패(원격이 앞서 있음)가 보고되면 해당 저장소에서 pull 후 재실행한다.

## 레지스트리와 세션 자동 동기화

- **registry.json**: 관리 대상 전역 스킬의 전체 목록(이름, 원본 경로, git 원격 URL, 저장소 내 상대경로, 제외 목록). `add`/`sync`/`remove` 때 자동 갱신되며 **globalize 원본 폴더**에 기록되므로 프로젝트 저장소에 커밋되어 다른 PC로 함께 이동한다. 직접 편집하지 않는다.
- **git 저장소 정보**: 원본이 git 저장소 안에 있고 원격(remote)이 등록되어 있으면 `sync` 때 URL이 사이드카·레지스트리에 자동 기록된다. 원격이 없으면 비어 있으며, 이 경우 새 PC 이전 시 clone 안내가 불가능하므로 원격 등록을 권장한다.
- **SessionStart 훅(`install-hook`)**: 사용자 전역 `~/.claude/settings.json`에 SessionStart 훅을 등록해 **모든 세션 시작 시 `autosync`**(전체 원본 → 전역 동기화 + 레지스트리 갱신)가 백그라운드로 돈다. 원본을 수정하면 다음 세션부터 자동 반영되므로 평소에 `sync`를 직접 부를 일이 거의 없다. 멱등이라 여러 번 실행해도 훅은 하나만 유지되고, 기존 다른 훅은 보존된다.
- `autosync`는 훅 전용 액션이다: 변경/문제가 있을 때만 출력하고 항상 성공(exit 0)으로 끝난다.

## 이전/복원 (새 PC 마이그레이션)

새 PC에서 전역 스킬 세트를 되살리는 순서:

1. globalize가 들어 있는 프로젝트 저장소를 clone(또는 복사)한다.
2. 그 프로젝트 폴더에서 `add globalize` 실행 → globalize 자신이 전역 등록되고 registry.json도 함께 전역으로 복사된다.
3. `restore` 실행 → 레지스트리의 각 스킬에 대해:
   - 레지스트리에 기록된 **원본 경로**가 존재하면 그대로 등록·동기화
   - 없으면 **PC에서 검색**(`.claude\skills\<이름>` 폴더; 기본은 고정 드라이브 최상위 폴더들에서 3단계 깊이, `GLOBALIZE_SEARCH_ROOTS` 환경변수(세미콜론 구분)로 검색 루트 지정 가능)
   - 그래도 없으면 기록된 **git 저장소 URL로 clone 안내**를 출력 → 사용자와 clone 위치를 정해 clone 후 `add <경로>`로 등록
4. `install-hook` 실행 → 세션 시작 자동 동기화 재설정.

`restore [경로]`로 다른 레지스트리 파일을 지정할 수도 있다(기본: 실행 중인 스크립트 옆의 registry.json — 전역 복사본에도 미러링되어 있음).

## 관리 흐름 (인자 없는 호출의 기본 동작)

사용자가 인자 없이 스킬을 호출하거나 "전역 스킬 관리/정리/확인"을 요청하면 다음 순서로 진행한다:

1. `list`를 실행해 전역 스킬 현황을 파악하고, 사용자에게 요약해 보여준다: 스킬 이름, 상태(동기화됨 / 원본과 다름 / 원본 없음 / 전역 전용), 원본 경로.
2. **원본과 다른 스킬이 있으면 AskUserQuestion 도구**로 어떻게 할지 묻는다:
   - multiSelect 질문으로, 원본과 다른 스킬 각각을 선택지로 제시한다 — label은 스킬 이름, description에 원본 경로와 상태를 넣는다. "모두 업데이트" 선택지를 첫 번째로(권장 표시), "업데이트하지 않음"을 마지막에 넣는다.
   - 선택된 스킬만 `update <이름>`을 실행하고 결과를 보고한다.
   - 선택지가 4개 제한을 넘으면 여러 질문으로 나눈다.
3. **원본 프로젝트의 git 관리**: `list`의 git 상태에 미커밋/미푸시가 있는 원본 프로젝트가 있으면, 동기화 처리 후 AskUserQuestion(multiSelect)으로 커밋+푸시할 프로젝트를 선택받는다 — 같은 저장소(root)를 쓰는 스킬들은 하나의 선택지로 묶고, label은 저장소 폴더 이름, description에 경로와 상태(미커밋 n, 미푸시 n)를 넣고, 마지막에 "지금은 하지 않음"을 둔다. 선택된 프로젝트는 각각 해당 저장소에서 `/git` 스킬의 기본 규칙대로 처리한다(`git -C <root> add -A` → diff 분석해 한국어 1줄 커밋 메시지 자동 생성 → commit → push; 원격이 없으면 `/git`의 공통 규칙대로 원격 연결을 질문). 사용자가 요청하지 않는 한 자동으로 커밋하지 않는다.
4. 모두 최신이면 그 사실만 보고한다. "원본 없음" 스킬이 있으면 원본 프로젝트가 이동/삭제된 것이므로, 새 경로로 `add` 재등록 또는 `remove`를 제안한다.
5. **제거는 사용자가 요청한 경우에만** 진행한다. 대상이 명시되지 않았으면 AskUserQuestion으로 선택받는다(label=스킬 이름, description=원본 경로, 마지막에 "제거하지 않음"). 전역 전용(관리 대상 아님) 스킬은 이 도구로 제거할 수 없음을 안내한다. 제거해도 원본은 남는다는 것을 함께 알린다. `remove`된 스킬은 레지스트리에서도 빠지므로 이후 `restore` 대상이 아니다.

사용자가 처음부터 대상과 작업을 명시한 경우(예: `/globalize update foo`, "foo 전역에서 빼줘")에는 질문 없이 바로 실행한다.

## 실행 위치가 두 곳임을 인지할 것 (경로 주의)

전역화된 스킬은 **어느 사본으로 실행되는지가 상황마다 다르다**: 원본 프로젝트 안에서 호출하면 프로젝트 쪽 스킬이, 다른 프로젝트에서 호출하면 전역 복사본이 로드된다. 따라서 —

- `<이 SKILL.md가 있는 폴더>`·`$PSScriptRoot`는 호출 시점에 **프로젝트 경로일 수도, `~/.claude/skills/<이름>`일 수도 있다.** 함께 복사되는 파일(스크립트끼리)의 상호 참조는 어느 쪽이든 동일하게 동작하므로 안전하다.
- 현재 작업 폴더(cwd)는 **호출한 프로젝트**다. cwd 기준 상대경로로 "원본 프로젝트의 데이터"를 찾으면 다른 프로젝트에서 깨진다.
- 원본 프로젝트의 데이터를 써야 하는 스킬(프로젝트 연결 스킬)은 데이터 경로를 **원본 프로젝트의 절대경로로 고정하고 환경변수로 재정의 가능**하게 한다. 그러면 어느 사본으로 실행돼도 항상 같은 데이터 하나를 본다 (예: cred는 저장소를 `E:\dev\globalize_skill\...\profiles` 절대경로로 고정하고 `CRED_STORE`로 재정의). 이 절대경로는 PC 이전 시 바뀌므로, `restore`/`add`로 재등록할 때 해당 스킬의 고정 경로도 함께 갱신해야 한다.

## 전역화 전 반드시 검토할 것 (중요)

`add`를 실행하기 **전에** 대상 스킬의 SKILL.md와 스크립트를 읽고 다음을 확인한다. 문제가 있으면 사용자에게 알리고 함께 고친 뒤 등록한다:

1. **프로젝트 상대경로 참조**: 위 "실행 위치가 두 곳" 규칙 위반 여부 — cwd 기준 상대경로나 "이 프로젝트 안의 데이터" 참조가 있으면 **절대경로 + 환경변수 재정의** 패턴으로 바꾼다.
2. **복사하면 안 되는 데이터**: 자격증명, 프로필, 백업, 대용량 데이터 폴더가 스킬 폴더 안에 있으면 `-Exclude`로 제외한다 (예: `-Exclude profiles,data`).
3. **자체 동기화 로직 유무**: 스킬이 자체적으로 전역 설치 로직을 갖고 있으면 globalize로 중복 등록하지 않는다.
4. **PowerShell 스크립트 인코딩**: `.ps1`은 반드시 **UTF-8 with BOM**이어야 한다(Windows PowerShell 5.1은 BOM 없는 UTF-8을 ANSI로 읽어 한글이 깨진다).

## 규칙

1. 전역 복사본을 직접 수정하지 않는다. 수정은 항상 프로젝트 원본에서 하고 `sync`로 반영한다. (install-hook이 설정되어 있으면 다음 세션 시작 때 자동 반영된다.)
2. `add`/`sync`/`restore` 완료 후 안내한다: **"전역 스킬은 새 세션부터 인식됩니다."**
3. `remove`는 전역 복사본만 지운다. 원본 삭제를 요청받은 경우에만 별도로, 사용자 확인 후 진행한다.
4. registry.json은 자동 생성물이다. 수동 편집하지 말고, 변경되면 프로젝트 저장소에 커밋되도록 둔다.
