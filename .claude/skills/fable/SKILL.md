# Claude Fable — 묻기 · 에이전트로 맡기기 (fable)

`/fable` 은 이 대화의 모델과 **따로** Claude Fable 을 쓴다. 지금 대화하는 모델을 바꾸는 것은 `/model` 이고, 이 스킬과는 다르다. 세 가지 방식이 있다:

| 방식 | 무엇 | Fable 이 할 수 있는 것 | 청구 |
|---|---|---|---|
| **묻기** `/fable <질문>` | `scripts/fable.py` 가 Anthropic API 로 claude-fable-5-2 를 **한 번** 부른다 | 글 답만 — 붙여 준 파일만 보고, 다른 파일을 열거나 고치거나 명령을 돌릴 수 **없다** | API 키(입력 $8 · 출력 $40 / 1M 토큰) |
| **키 에이전트** `/fable agent <일>`(키가 있으면 이쪽이 먼저) | `scripts/fable_agent.py` 가 Claude Code 를 헤드리스로(`claude -p`) 띄운다 — 그 프로세스에만 API 키를 준다(claude-fable-5-2) | 저장소를 뒤지고 파일을 고친다(작업 폴더 안). **명령 실행은 허용 규칙이 있을 때만** — 없으면 자동 거절되고 보고에 적힌다 | **API 키**(끝 줄에 실제 비용) |
| **세션 에이전트** `/fable agent via=session <일>` | `Agent` 도구로 Fable 모델 하위 에이전트를 띄운다 | 도구 전부 — 저장소를 뒤지고, 파일을 고치고, 검사·명령을 돌리고, 끝에 보고(이 세션의 권한대로) | 이 세션의 계정(API 키 안 씀) |

하위 에이전트는 **키 에이전트를 먼저** 쓴다(2026-11-13 사용자 "fable 스킬에 서브에이전트 사용하는 api key 가 있는데 가급적 그걸 우선 사용해 주길 바람" → "추가해줘"). `/fable` 로 부르지 않았어도, 이 스킬이 있는 환경에서 하위 에이전트에 일을 나눠 맡길 때 같은 차례다.

묻기 쪽 명령(`anthropic` 파이썬 패키지 필요 — 없으면 `pip install anthropic`):

```
python -X utf8 "<이 SKILL.md가 있는 폴더>/scripts/fable.py" <인자…>
```

## 인자에 따라

| 사용자 입력 | 할 일 |
|---|---|
| `/fable agent <일>` · `/fable 에이전트 <일>` | 키가 있으면(`key list`) 아래 **「키 에이전트로 맡기기」**, 키가 없거나 `via=session` 이면 **「세션 에이전트로 맡기기」**. 일이 명령 실행(검사·빌드·서버)에 기대는데 허용 규칙이 없으면 → 키 에이전트로 고치게 하고 검사는 부른 세션이 돌린다(「검사 고리」), 그것으로 안 되는 일(명령을 돌려 봐야 다음을 정하는 조사 등)만 세션 에이전트로 — 어느 쪽으로 돌렸는지 한 줄로 알린다 |
| `/fable key <API 키 …>` | 키를 **더한다**(있던 키는 그대로 — 차례의 끝에). 키를 **표준 입력으로** 넘긴다(명령 줄 인자에 안 남게 · 공백·줄로 여럿): `printf '%s' '<키>' \| python -X utf8 ".../fable.py" key add` — 저장 전에 작은 호출로 키를 확인한다(비용 토큰 수백 개 · 안 되는 키는 저장하지 않음). `name=이름` 이면 `--name 이름`(키 하나일 때), `first` 면 `--first`(맨 앞 차례로), 확인 없이 저장하라고 하면 `--no-test`. 이미 등록된 키면 이름만 바꾼다. `key set` 도 같다(옛 이름) |
| `/fable key` · `key list` · `key status` | `key list` — 등록한 키 목록(앞 7자…끝 4자 · 이름 · 저장 때 · 쉬는 중이면 까닭과 남은 시간), 다음 호출의 차례, 등록하지 않아 안 쓰는 키가 다른 곳에 있는지 |
| `/fable key test [선택]` | `key test [선택]` — 작은 호출로 등록한 키를 모두(또는 고른 키 하나) 확인한다. 안 되는 키는 차례가 뒤로 밀리고, 되면 제 차례로 돌아온다 |
| `/fable key first <선택>` | `key first <선택>` — 고른 키를 맨 앞 차례로(선택 = `key list` 의 번호 · 끝 네 글자 이상 · 이름) |
| `/fable key remove <선택>` · `remove all` | `key remove <선택>` · `key remove --all` — 고른 키(모두)를 지운다. 키가 여럿인데 고르지 않으면 거절된다. 지우기 전에 한 번 확인한다 |
| `/fable <글>` (그 밖 모두) | 글이 **손이 가는 일**이면(파일을 고치라·만들라·구현하라·적용하라, 검사·명령을 돌리라, 저장소를 보고 찾으라, 「직접」·「에이전트로」) 「에이전트로 맡기기」. 묻는 것·검토·의견·설명이면 「묻기」. 애매하면 묻기(싸고 되돌릴 게 없다) |
| `/fable` (인자 없음) | 무엇을 물을지·맡길지 짧게 되묻는다. 키가 없으면 `key list` 결과와 함께 키 등록을 안내한다(세션 에이전트는 키가 없어도 된다) |

### 키를 다룰 때

- 사용자가 준 키를 **답에 되풀이해 적지 않는다**(끝 네 글자만). 키를 파일·명령 줄 인자·커밋에 남기지 않는다 — 표준 입력으로만 넘긴다.
- 저장 위치는 `~/.claude/fable/config.json`(스킬 폴더 밖 — 스킬 원본은 git 저장소다 · 키 목록 `{"keys": [{key, name, saved}]}` — 옛 꼴 `{"api_key": …}` 도 읽고 다음 저장 때 새 꼴로). env `FABLE_CONFIG` 로 바꿀 수 있다.
- **등록한 키**의 차례: env `FABLE_API_KEY`(있으면 맨 앞) → 저장한 키들(더한 차례 · `key first` 로 앞으로). 등록한 키가 하나도 없을 때만 전처럼 env `ANTHROPIC_API_KEY` → `~/.claude/settings.json` 의 `env.ANTHROPIC_API_KEY` 의 첫 키 하나를 쓴다 —
  등록한 키끼리만 넘어가고, 등록하지 않은 다른 계정의 키로는 넘어가지 않는다. 저장한 키는 Claude Code 자체의 로그인에는 영향이 없다.
- **다음 키로 넘어가는 때**: 키 거절(401) · 크레딧 부족 · 권한 없음(403) · 사용 한도(429). 서버 과부하(529)·서버 오류·연결 오류는 키 탓이 아니라 넘어가지 않는다. 묻기는 답을 받기 시작한 뒤의 오류에서도 넘어가지 않는다(답이 섞이지 않게).
  쓸 수 없던 키는 지우지 않고 **차례만 잠시 뒤로** 미룬다(키 거절·권한 24시간 · 크레딧 1시간 · 한도 retry-after — 기록 `~/.claude/fable/key_state.json` 은 키 글이 아니라 지문만). 그 키로 다시 되면(호출 · `key test`) 제 차례로 돌아온다.
- 넘어갔으면 끝 줄에 「넘어간 키: …」 와 실제로 쓴 키가 나온다 — 사용자에게 그대로 알린다(다른 키·다른 계정으로 청구되었을 수 있다).
- 키를 처음 저장했으면 한 줄로 알린다: 대화에 붙여 넣은 키는 이 대화 기록에 남는다 — 걱정되면 Console 에서 새 키를 만들어 다시 저장하고 옛 키를 지우면 된다.

## 묻기

1. **질문 글을 만든다** — Fable 은 이 대화를 못 본다. 사용자의 질문에 이 대화의 맥락이 필요하면(「위 코드 봐 줘」 · 「이 설계 어때」) 필요한 맥락을 질문 글에 함께 적는다.
   사용자가 파일 경로를 주거나 「이 파일」 이라고 가리키면 `--file <경로>` 로 붙인다(여러 개 가능 · 그림 png/jpg/gif/webp · PDF 도). 파일 내용을 질문 글에 다시 붙여 넣지 않는다.
   큰 파일을 통째로 보내기 전에 크기를 보고, 비용이 크면(수십만 토큰) 필요한 부분만 보낼지 사용자에게 묻는다.
2. **질문 글은 임시 파일로** 넘긴다(셸 따옴표 문제를 피함 — 세션의 scratchpad 폴더에): `--prompt-file <파일>`. 답이 길 수 있으니 `--out <답 파일>` 도 준다.
3. **실행**: Bash 로 위 명령(`--prompt-file … --out … [--file …] [--effort …]`). Fable 은 한 답에 몇 분 걸릴 수 있다 — timeout 을 600000 으로, 아주 큰 일은 `run_in_background` 로 돌리고 끝나면 이어서.
   - effort: 기본 `high`. 사용자가 `effort=…` 을 적으면 그 값. 가벼운 질문이면 `medium`.
   - 거절(refusal)에 대비해 서버 쪽 대체가 기본으로 켜져 있다 — 끝 줄의 「대체: …」 가 그 표시. 사용자가 원하지 않으면 `--no-fallback`.
4. **보여 주기**: Fable 의 답을 **고치거나 줄이지 않고 그대로** 보여 준다(「Fable 의 답」 이라고 밝히고). 그 뒤에 끝 줄(모델 · 토큰 · 대략 비용)을 한 줄로.
   사용자가 물으면 그 답에 대한 내 의견을 따로 덧붙일 수 있다 — 답과 섞지 않는다.
5. **실패**: 종료 코드 1 = 키 없음·인자 오류(키가 없으면 `/fable key <API 키>` 안내) · 2 = API 오류(「쓸 수 있는 키가 없습니다」 면 등록한 키가 모두 키 거절·크레딧 부족 등 — 까닭을 그대로 알리고 크레딧 충전이나 키 추가를 안내) · 3 = 대체 모델까지 거절. 같은 요청을 그대로 되풀이하지 않는다.

## 키 에이전트로 맡기기 (API 키로 청구)

`scripts/fable_agent.py` 가 Claude Code CLI 를 헤드리스로 띄운다 — 자식 프로세스의 env 와 임시 플래그 설정(`--settings` — 실행이 끝나면 지움)에 API 키를 넣어 **그 키로 청구**되게 한다(키 차례·넘어가기는 묻기와 같다). 첫 메시지의 키 출처가 API 키가 아니면 스크립트가 바로 끊는다(다른 계정으로 청구되지 않게).
키 탓으로(키 거절 · 크레딧 부족 · 권한 · 사용 한도) 실패하면 그 키를 뒤로 미루고 다음 키로 다시 띄운다 — 아직 도구를 하나도 안 썼으면 같은 일감으로 처음부터, 일을 하던 중이었으면 **같은 세션을 다음 키로 이어서**(`--resume` + 「끊긴 곳부터 이어서」 — 맥락이 남는다). 비용 상한은 여러 번 띄운 것을 합쳐 센다.
(플래그 설정으로도 키를 주는 까닭: Claude Code 는 사용자 설정 `~/.claude/settings.json` 의 `env` 를 제 env 에 얹어, 거기 `ANTHROPIC_API_KEY` 가 있으면 자식 env 로 준 키를 덮어쓴다 — 2026-11-24 실측: 그 전까지 키 에이전트는 등록한 키가 아니라 settings 의 키로 청구되었다.)

```
python -X utf8 "<이 SKILL.md가 있는 폴더>/scripts/fable_agent.py" --prompt-file <일감.md> --out <보고.md> --log <기록.jsonl> --cwd <프로젝트 폴더> [--effort high] [--perm edit|plan] [--allow "<도구 규칙>" …] [--budget 20] [--resume <세션 id>]
```

1. **일감 글**(`--prompt-file` — 세션의 scratchpad 폴더에 쓴다): 아래 「세션 에이전트로 맡기기」 2번과 같은 내용(맡길 일 그대로 + 필요한 맥락 · 볼 파일의 **경로** · 범위 · 하지 말 것 · 끝 보고 형식). 키 에이전트도 이 대화를 못 본다.
   허용 규칙 없이 띄울 때는 한 줄 더: 「명령은 거절될 수 있다 — 검사를 돌리지 못했으면 무엇을 돌려야 하는지 보고에 적어라」.
2. **실행**: Bash 로 위 명령. 일이 길면(몇 분 넘게) `run_in_background` — 끝나면 알림이 온다. 그 전에는 결과를 짐작하지 않고, 같은 파일을 건드리지 않는다. 진행(도구 이름 한 줄씩)은 표준 출력, 원문은 `--log`.
   - effort: 기본 `high`. 사용자가 `effort=…` 을 적으면 그 값.
   - 비용 상한 `--budget`(달러 — 기본 20, 사용자가 `budget=…` 을 적으면 그 값 · 0 = 없음). 넘으면 멈춘다(종료 코드 3) — 끝 줄의 세션 id 로 이어 갈 수 있다.
   - 여럿을 함께 띄울 때는 **4개까지**, 서로 다른 파일을 맡긴다(Windows 에서 `claude -p` 를 많이 띄우면 일부가 죽는다).
3. **권한** — 키 에이전트는 **이 세션의 권한 검사를 받지 않는 별도 프로세스**다. 그래서 기본이 좁다:
   - `perm=edit`(기본): 파일 읽기·찾기 + 작업 폴더 안 파일 고치기. 물어야 하는 것(명령 실행 등)은 **자동 거절**되고 끝 줄·보고에 무엇이 거절됐는지 나온다. `perm=plan` 은 읽기만.
   - 명령을 돌리게 하려면 **사용자가 정한** 규칙이 있어야 한다: 사용자가 `allow="Bash(python -X utf8 -m pytest:*)"` 처럼 적어 준 것(`--allow` 로 그대로 넘긴다), 또는 사용자·프로젝트 설정 파일의 `permissions.allow`(Claude Code 가 그대로 적용한다).
     **`--allow` 를 내 판단으로 지어 넣지 않는다** — 사용자가 적지 않은 명령 권한이 필요하면 무엇이 왜 필요한지 알리고 묻는다.
   - 모든 것을 묻지 않고 하는 방식(bypass·auto)은 스크립트에 없다. 이 세션의 권한 검사가 그런 자식 프로세스를 띄우는 것을 막기도 한다(2026-11-13 실측 — 「감독을 벗어남」 으로 거절). 사용자가 원하면 사용자가 정한다.
4. **검사 고리**(허용 규칙이 없어 키 에이전트가 검사를 못 돌릴 때): 키 에이전트가 고치고 끝남 → **부른 세션이 검사를 돌림** → 떨어진 것이 있으면 그 출력을 새 일감 글로 적어 `--resume <세션 id>` 로 같은 에이전트에 돌려줌(맥락이 남아 있다) → 통과할 때까지. 사용자에게는 누가 무엇을 돌렸는지 그대로 말한다.
5. **보여 주기**: `--out` 의 보고를 **고치거나 줄이지 않고 그대로** 보여 준다(「Fable 키 에이전트의 보고」 라고 밝히고). 바로 뒤에 `git status --short`(git 저장소면)로 **실제로 바뀐 파일**, 그리고 끝 줄(모델 · 쓴 키 · 턴 수 · 시간 · **비용 — API 키로 청구** · 넘어간 키 · 권한 거절)을 한 줄로.
   보고가 「검사 통과」 라고 해도 결과가 중요하면 그 검사를 한 번 더 돌려 확인한다. 내 의견은 사용자가 물을 때 따로.
6. **이어 하기**: 같은 일을 이어 가는 요청은 새로 띄우지 않고 `--resume <끝 줄의 세션 id>` + 새 일감 글(실측: 앞 대화를 기억한다).
7. **실패**: 종료 코드 1 = 키·`claude` 실행 파일·인자 없음(키가 없으면 `/fable key <API 키>` 안내 — 급하면 세션 에이전트로 할지 묻는다) · 2 = CLI 오류·실패 결과(「쓸 수 있는 키가 없습니다」 = 등록한 키 모두 키 탓으로 실패 — 까닭을 알리고, 급하면 세션 에이전트로 할지 묻는다 · 일을 하던 중이었으면 끝 줄의 `--resume` 으로 이어 갈 수 있다) · 3 = 비용 상한 · 4 = API 키로 청구되지 않아 끊음(env 의 다른 인증이 먼저 잡힘 — 그대로 알린다).
   에이전트가 끝내지 못했으면 어디까지 했는지(바뀐 파일)를 보이고, 되돌릴지 이어 갈지 사용자에게 묻는다.

실측(2026-11-13, Claude Code 2.1.321 · Windows): 첫 메시지 `apiKeySource: ANTHROPIC_API_KEY` · 모델 claude-fable-5-2 · 파일 읽고 쓰기 됨 · 허용 안 한 `python --version` 은 거절되어 `permission_denials` 에 나옴 · `--allow "PowerShell(python --version)"` 를 주면 그 명령만 돎 · `--resume` 이 앞 대화를 이음 · 작은 일 하나에 $0.14~0.20(시스템 프롬프트 몫이 바닥).
실측(2026-11-24, Claude Code 2.1.321): 키 탓 실패는 assistant 메시지의 `error`(잘못된 키 = `authentication_failed` · 401 「Invalid API key」, 크레딧 = `billing_error` · 400 「Credit balance is too low」)와 결과의 `terminal_reason: api_error` · `api_error_status` 로 온다(`duration_api_ms` 는 0) ·

## 세션 에이전트로 맡기기 (이 세션의 계정으로 청구)

스크립트는 쓰지 않는다. `Agent` 도구로 **Fable 모델** 하위 에이전트를 띄워 일을 맡기고, 그 보고를 사용자에게 전한다. 키가 없을 때 · 사용자가 `via=session` 을 적었을 때 · 명령을 돌려 가며 해야 하는 일인데 허용 규칙이 없을 때 쓴다. 하위 에이전트의 Fable 판은 Claude Code 가 정한다(2026-11-13 확인: `model: "fable"` → claude-fable-5-1 — 묻기의 claude-fable-5-2 와 다를 수 있다).

1. **띄우기**: `Agent` 도구 — `subagent_type: "general-purpose"`(도구 전부) · `model: "fable"` · `description` 은 3~5 단어. `effort` 는 사용자가 `effort=…` 을 적었을 때만 그 값을 넘기고, 안 적었으면 비워 둔다.
   `isolation: "worktree"` 는 사용자가 「작업 트리 따로」·「본 저장소 건드리지 말고」 라고 할 때만.
2. **일감 글(prompt)** — 하위 에이전트는 이 대화를 못 본다. 그 글만 보고 일하니 다음을 담는다:
   - 맡길 일을 사용자가 말한 대로(줄이거나 바꾸지 않는다) + 그 일에 필요한 이 대화의 맥락(이미 확인된 사실 · 해 본 것 · 안 되는 것 · 사용자가 정한 기준).
   - 볼 파일·문서·사양서의 **경로**(내용을 되붙이지 않는다). 프로젝트에 규칙 파일(CLAUDE.md · 할 일별 전제 파일 등)이 있으면 먼저 읽으라고 적는다.
   - 범위: 어디까지 고쳐도 되는지, 건드리면 안 되는 파일. 고칠 때는 작은 범위로(Edit — 파일 통째 다시 쓰기 금지), 이미 있는 코드·검사를 되돌리거나 지우지 않는다.
   - 하지 말 것: 묻지 않고 커밋·푸시·`checkout`·`reset`·`stash`·파일 삭제·설정 변경 — 필요하면 보고에 적는다. 다른 세션·에이전트가 같은 파일을 고치고 있는 듯하면(`ListAgents` · 예상 밖 변경) 멈추고 보고한다.
   - 끝 보고 형식: ① 고친 파일과 무엇을 왜 ② 돌린 검사·명령과 **실제 결과**(떨어진 것도 그대로) ③ 못 한 것·판단이 필요한 것. 추측을 사실처럼 쓰지 않는다.
3. **기다리기**: 하위 에이전트는 뒤에서 돈다 — 끝나면 알림이 온다. 그 전에는 결과를 지어내거나 짐작하지 않고, 같은 파일·주제를 건드리지 않는다. 사용자가 그동안 물으면 「아직 도는 중」. 겹치지 않는 다른 일은 해도 된다. 서로 안 겹치는 일이 여럿이면 에이전트를 한 메시지에 여럿 띄운다 — 같은 파일을 둘이 고치게 하지 않는다.
4. **보여 주기**: 보고를 **고치거나 줄이지 않고 그대로** 보여 준다(「Fable 에이전트의 보고」 라고 밝히고). 보고는 모델의 말이다 — 바로 뒤에 `git status --short`(git 저장소면)로 **실제로 바뀐 파일**을 같이 보인다. 보고가 「검사 통과」 라고 해도 사용자가 원하거나 결과가 중요하면 그 검사를 한 번 더 돌려 확인한다. 내 의견은 사용자가 물을 때 따로 — 보고와 섞지 않는다.
   끝 알림의 usage(토큰 수)를 한 줄로 덧붙인다 — 이 세션 계정으로 청구되는 것이고 API 키 비용이 아님을 밝힌다.
5. **이어 하기**: 같은 일을 이어 가는 요청(「거기서 ~도 해 줘」·「다시 봐 줘」·결과에 대한 지적)은 새 에이전트가 아니라 **같은 에이전트에 `SendMessage`** 로 보낸다(맥락이 남아 있다). 다른 일이면 새로 띄운다.
6. **실패·권한**: 에이전트가 권한이 막혔다고 보고하면 내가 대신 하지 않는다 — 사용자에게 그대로 알리고 묻는다. 에이전트가 끝내지 못했으면 어디까지 했는지(바뀐 파일)를 보이고, 되돌릴지 이어 갈지 사용자에게 묻는다.
